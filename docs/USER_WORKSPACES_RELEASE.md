# 独立用户工作区与界面升级说明

本分支将项目从环境变量管理的单账号工作台，升级为 PostgreSQL 持久化的独立用户工作区，并统一整理界面与可靠性问题。

## 主要变更

### 用户账号与数据隔离

- 用户名/密码注册、登录与退出；注册后自动进入自己的空工作区。
- Argon2id 密码哈希、数据库可撤销会话、认证请求限流；退出后旧凭据失效。
- 内容、聊天、任务、研究运行、素材、日历、发布记录及幂等记录按用户隔离。
- 记忆文件与冻结提示词缓存按用户隔离；后台任务从持久化记录恢复所属用户。
- 防止跨用户资源引用、线程 ID 复用与批量修改。
- 前端账号切换与浏览器缓存恢复会重建工作区；API 响应使用 `Cache-Control: no-store`。

### 界面与操作体验

- 统一浅雾灰、墨绿的视觉体系，重排侧栏、内容库、聊天、创作、日历、统计、记忆与账号页面。
- 内容库采用列表与阅读区；聊天扩大消息区并收纳模型设置，桌面发送区保持可见。
- 中文化组件，改善手机排版、键盘焦点与页面滚动恢复。
- 修复会话切换竞态、标题点击误触重命名、初始路由未就绪导致的登录循环。

### 可靠性

- 上传文件按 1 MiB 分块复制，减少整文件读取带来的内存开销；失败时清理残留文件。
- 媒体元数据在事务提交前准备完毕，避免提交后读取异常导致误删文件。
- 防止终态失败任务因重复队列投递而重跑；补齐监控指标标签。
- 修正 Windows 专属测试边界和测试包导入冲突。

## 升级前须知（有破坏性配置变更）

1. 先备份 PostgreSQL 与应用数据目录，再停止 API/worker。
2. 移除 `AUTH_ENABLED`、`AUTH_USERNAME`、`AUTH_PASSWORD` 和旧 `AUTH_STREAM_TICKET_SECONDS` 配置。所有环境均需设置 `AUTH_SECRET_KEY`，鉴权不再支持关闭。
3. 执行 `alembic upgrade head`，升级至 `0009_user_workspaces`。
4. 旧记录会保留在禁用的迁移账号下，新注册者不会自动获得旧数据。
5. 如需认领旧工作区，执行 `python scripts/claim_legacy_workspace.py --username YOUR_USERNAME`，按提示私下输入密码。旧记忆文件会复制到用户目录，原件保留作备份。
6. 启动服务并重新登录；原单管理员 token 已失效。

完整契约与生产部署注意事项见 [安全与迁移说明](PHASE0_SECURITY_AND_MIGRATIONS.md#postgresql-accounts-and-workspace-migration)。

## 当前边界

- 采用用户名密码注册，尚未接入邮箱/短信验证或密码找回。
- 模型供应商配置仍由服务端统一管理。
- 未执行对外平台发布；未将本地密钥、数据库备份、日志或构建产物纳入提交。
