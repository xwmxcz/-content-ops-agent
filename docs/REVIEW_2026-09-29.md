# 2026-09-29 项目审查与功能优化

本次审查及后续修复覆盖前端主要页面、API 与存储契约、账号隔离、内容生成/打磨、后台任务、发布、日历、效果数据、部署配置及现有测试。优先修复可复现的功能缺陷和数据一致性问题；保留现有账号模型，未新增运行时依赖。后续修复为流水线增加运行租约，需要执行迁移 `0011_pipeline_run_leases`。

## 已完成的修复

| 模块 | 原有问题及影响 | 改进后的行为 |
| --- | --- | --- |
| 内容库搜索 | 只在最近 100 条的截断正文中搜索，旧稿和正文末尾无法命中 | 服务端搜索完整标题/正文，支持筛选组合；每页 30 条加载更多；输入防抖、忽略过期响应、明确显示失败 |
| 内容库详情与上传 | 快速切换内容时旧详情/素材/发布记录覆盖新内容；批量上传可能中途改绑另一稿件 | 按请求序号和内容 ID 隔离响应；整批上传固定使用开始时的内容 ID |
| 内容打磨 | 输入新 ID 未加载时可能处理未预览稿件，重复点击会创建多个任务 | 所有打磨操作使用已预览稿件 ID；加载失败清理旧预览；执行期间阻止重复提交 |
| 效果数据 | 保存期间切换内容会串入旧记录；旧读取可能覆盖新保存结果 | 保存结果绑定内容版本；成功写入使更早读取失效；防止重复提交 |
| CSV 导入 | 缺失列、空浏览数、重复表头及错误分隔可能产生错误读数 | 提交前拒绝缺列、额外列、空浏览数、重复表头及不安全内容 ID |
| 发布日历 | 允许翻到任意月份，却只查询未来 60 天；添加后无法纠错 | 按可见月份及相邻日期加载；保留独立的未来 60 天汇总；支持编辑和确认删除本地计划；修改日期后跳到对应月份 |
| 日历边界 | 日期范围、平台名和已有平台排期的操作边界不明确 | 校验范围和平台名；编辑/删除受工作区隔离；只允许修改 `planned` 本地计划，避免误把本地删除当作平台撤销 |
| 发布请求去重 | 去重指纹遗漏正文、素材、可见性等参数，修改后可能返回旧任务 | 指纹覆盖完整请求；同一键配不同参数返回冲突错误 |
| 发布执行去重 | HTTP 未提供去重键时，同一后台任务重跑可能再次发布 | 按 publication ID 保证同一发布任务执行去重；用户新建的独立发布任务仍可执行 |
| 发布输入与状态 | 素材 ID 被静默丢弃/重排、空选择被当作全选、无法清空标签、入队失败仍显示排队中 | 保留素材顺序并严格校验；允许清空标签；拒绝空正文；入队失败回写失败；正确识别 MCP 布尔及中英文登录状态 |
| 自动重试 | background 模式没有真正调度重试；RQ worker 未开启 scheduler；前端遇到 failed 立即停止 | 补齐两种调度；API 返回重试字段；前端识别等待重试并继续轮询；等待重试可取消 |
| 任务并发与回收 | 旧 worker 的完成/失败写入可能覆盖取消或新租约；回收后入队失败会永久停留 queued | 条件写入同时校验状态及租约持有者；回收事务保留待派发标记，后续扫描可再次派发；终态 pipeline 重复投递不再调用模型 |
| 流水线进程中断 | run 没有租约，worker 崩溃或队列丢失后长期停在 `running`，无法续跑 | 排队期限、独立执行标识、运行心跳与过期回收；到期转为可续跑失败并保留 checkpoint；GET / SSE / 续跑入口也会检查过期，覆盖无独立 reaper 的开发环境 |
| 流水线并发与取消 | 恢复后旧进程可能写入事件或结果，取消清理依赖存活的 worker | 计划、事件、checkpoint 和最终内容写入均校验有效租约；取消事务直接清理 checkpoint；无租户 reaper 仍按每条 run 的所有者保存事件 |
| 普通任务重复投递 | 同一进程复用租约标识，重复投递可能释放正在执行任务的租约 | 每次投递使用唯一标识；启动检查持有者及有效期，失败的投递不能释放其他执行的租约 |
| 效果分析 | 录入的阅读、点赞、评论、分享没有形成分析页面 | 新增效果摘要、平台比较、创建日期分组图与前 10 名；按范围/平台筛选，显示读数覆盖，区分未录入与真实零值 |
| 并发素材上传 | 数量检查与落库分离，并发请求可能超过上限 | 上传、素材删除和内容删除共用内容行锁；事务内核对容量和分配顺序；失败清理本次文件，内容已删除时返回 404 |
| Chat 与首页反馈 | 快速搜索/切换会话时旧响应回写；首页请求失败与空结果混淆 | 搜索、列表、分页和会话恢复过滤过期响应；侧栏刷新失败不破坏成功回复；首页分区独立重试、保留并标注旧数据，未知值不显示为零 |

## 效果指标口径

- 范围依据**内容创建日期**，包括今天及之前的所选天数，不包含未来日期；图表按内容创建日期分组。
- 每个内容 / 平台取最近一条累计读数，允许新录入值低于旧值。同时间记录按 ID 决定先后。
- 浏览、点赞、评论、分享按平台分别累计；互动率为总互动除以总浏览，不是各稿件比例的平均数。零浏览时互动率不可计算。
- 数据覆盖按有读数的内容去重；同一稿件在不同平台的浏览不是去重用户数。未录入不当作零阅读，也不把累计读数解释为期间增量。
- 内容分母与最新指标通过一次 SQL 读取，使用同一 PostgreSQL 快照，避免查询期间新增内容导致负的缺失数或覆盖率超过 100%。

## API 兼容性

- `GET /api/content` 新增可选 `q`，保留列表响应和 `limit` / `offset` / `status` / `content_type`；按创建时间、ID 倒序稳定排序。搜索为大小写不敏感的字面子串匹配，`%`、`_` 不作为通配符。
- `GET /api/calendar/events` 新增成对的 `start_date` / `end_date`，闭区间最多 366 天；原有 `days` 查询保持兼容。
- 新增 `PUT /api/calendar/events/{event_id}` 与 `DELETE /api/calendar/events/{event_id}`。跨工作区或不存在返回 404，非本地待执行计划返回 409。
- Job 响应增加 `next_retry_at`、`max_retries`、`error_type`，既有字段保持不变。
- 新增 `GET /api/stats/performance`，支持 `days`（1–365，默认 30）及可选 `platform`；原 `/api/stats` 及 Agent 使用的效果聚合接口保持兼容。
- Run 响应增加 `worker_id`、`lease_expires_at`、`heartbeat_at`；回收事件 `run_failed` 带 `code: worker_lost`，前端可从断点继续。恢复为用户显式操作，不自动重复执行模型步骤。
- 发布素材参数从静默容错改为明确拒绝无效选择；这是有意的正确性修复。

## 部署要求

首轮未改变 schema；**包含后续修复的当前版本必须迁移**。先停止或排空旧 API、worker、reaper，再执行 `alembic upgrade head`，构建前端后统一启动新版本，避免旧 worker 绕过新租约校验。迁移给既有 `running` 行设置 5 分钟宽限期，不删除内容或 checkpoint。

默认排队期限 300 秒，租约 300 秒、心跳 30 秒、reaper 周期 60 秒；健康的 reaper 且无积压时，最后一次心跳后约 300–360 秒可将中断执行转为失败。无 reaper 时，用户读取 / 订阅 / 续跑会触发到期检查；无人访问时不承诺主动回收。慢队列可调整 `PIPELINE_DISPATCH_TIMEOUT_SECONDS`。运行租约必须大于心跳间隔。

本次仅在一次性测试库验证迁移与应用，没有对业务数据库执行迁移，也没有部署服务。
